# Remote Monitor v0.1.57 — PowerSI 전경 전환 완료 확인

휴대폰 사내 KI-Messenger → Win7 Master → 사내망 Win11 Slave로 업무 PC의 상태를 확인하는 프로젝트입니다. 화면·원문 판독은 Slave와 **같은 PC의 loopback LM Studio / 로컬 모델**에서만 수행합니다. 진행률을 추측하지 않습니다.

현재 시험은 **Slave만** 사용합니다. [현재 시험 방법](SLAVE-TEST.md), [목적·이력·개발 인수인계](HANDOFF.md)를 먼저 읽으세요.

## 이번 변경

- v0.1.56에서 활성화 요청과 Windows 응답이 성공했는데 실제 창 전환보다 먼저 실패 처리된 경합을 수정합니다. 요청은 한 번만 보내고, 실제 전경 HWND가 목표와 같아질 때까지 최대1초·25ms 간격으로 읽기만 합니다. 이전 창/일시적인 전경 없음은 기다리며 제3의 창이 나타나면 즉시 중단합니다.
- 활성화 확인이 끝난 시점의 창 상태와 경과 시간을 성공·실패 모두에 기록합니다. 무응답/목표 미도달 시간 초과/제3의 창 개입을 구분합니다. 최대화·복원·추가 클릭·강제 전환 재시도는 없습니다.
- PowerSI의 대상 확인·전경 전환이 성공한 뒤에만 Slave를 잠시 최소화합니다. 준비 실패 때문에 뒤의 탐색기 등이 드러나는 순서를 없앴습니다. 전경 전환 한 번·제한된 Windows 응답 대기·정확한 대상 확인은 유지합니다.
- 로그에 선택한 창의 HWND/PID·root/owner·Windows 최소화 판정·창 위치·현재 전경 PID를 숫자로 기록합니다. 창 제목·문서명·본문은 기록하지 않습니다. 다른 앱의 창은 대상 PID 목록에 없으면 선택하지 않습니다.
- 확인된 Output 본문 전체가 단색으로 비어 있으면 **보이는 내용 없음**으로 표시하고 클릭·복사·OCR을 생략합니다. 전체 버퍼·화면 밖 과거 로그가 비었다는 판정은 아닙니다. 커서/텍스트/무늬가 남아 판단할 수 없으면 빈 것으로 단정하지 않습니다.
- **새 화면 두 방식 비교** 한 번으로 현재 세션의 모든 PowerSI 프로세스를 PID 순서로 수집합니다. 최초 수동 클릭·Ctrl+A/C 학습은 없습니다.
- 각 PID·시작 시각·세션을 확인하고 해당 창을 전경으로 가져옵니다. **PowerSI 최대화·복원·크기 변경은 하지 않습니다.** 최소화된 창은 건너뜁니다. 같은 PID에 여러 창이 있으면 임의 선택하지 않습니다.
- 로컬 모델이 Output 영역을 찾고 픽셀 본문 경계를 검증합니다. 자동 복사 worker가 새 화면에서 다시 검증한 뒤 선택 해제 클릭 → 깨끗한 캡처 → Ctrl+A/C → 선택 정리를 수행합니다.
- OCR은 복사 worker의 **깨끗한 캡처 하단 최대256픽셀**을 사용합니다. 위치 모델을 다시 부르지 않습니다. 전체 복사 원문과 OCR 범위는 다릅니다.
- 한 창이 실패하거나 시간 제한에 걸려도 다음 PID를 진행합니다. 결과 목록에서 PID를 선택해 비교하고 **진단 ZIP 한 번에 모든 PID 결과**를 저장합니다.

**v0.1.57은 현장 미검증입니다.** v0.1.56 로그에서는 두 PowerSI 모두 정확한 PID/독립된 최상위 창·최소화 아님을 확인했지만 SC_FOREGROUND_WAIT_MISMATCH로 각각296/282ms에 중단됐습니다. 두 번째 대상 시작 때 첫 번째 PowerSI가 실제 전경이었던 기록이 있어, 첫 번째의 전환 완료보다 검사가 앞선 정황을 확인했습니다. 모델·복사 단계는 실행되지 않았습니다. 다른 앱을 닫거나 PowerSI를 수동 선택하는 우회 시험은 요구하지 않습니다.

## Pending과 입력 경계

Windows 메시지 응답을 제한시간 안에 확인하지 못하면 **SC_PENDING**으로 표시하고 전경 전환·클릭·키 입력을 진행하지 않습니다. 자동 입력 직전에도 검사하며, 입력 도중 무응답이 되면 그 시점 이후 추가 입력을 중단합니다. 이것은 **Windows 응답 없음** 검사이며, UI는 응답하면서 내부 시뮬레이션 단계만 pending인 상황까지 판정하지 못합니다. 해당 구간의 식별과 무입력 관측 정책은 후속 과제입니다.

전경 요청 거부/무응답은 SC_FOREGROUND_* 코드로 건너뜁니다. SC_FOREGROUND_WAIT_TIMEOUT은 실제 목표 창이1초 내 전경이 되지 않음, SC_FOREGROUND_WAIT_MISMATCH는 대기 중 제3의 창이 나타남입니다. 강제 클릭·Alt키·최대화로 우회하지 않습니다. 입력 중 사용자가 마우스를 움직이거나 다른 창이 가리면 중단합니다. 잠금 화면·연결 해제·최소화는 지원하지 않습니다.

Slave 자체 창만 **대상 준비 성공 후** 수집 동안 잠시 최소화했다가 복원합니다. 준비 실패이면 Slave도 최소화하지 않습니다. PowerSI의 위치·크기는 변경하지 않습니다. 클립보드는 복사한 Output으로 바뀌고, 커서는 사용자 이동이 없을 때만 되돌립니다. 자동 복사 설정을 끄면 전경 전환·입력 없이 직독/화면 판독만 하며 수동 복사를 재요구하지 않습니다.

## 결과와 비교

메인 창 Output 결과 목록에 PID별 수집 코드가 표시됩니다. **결과 비교 보기** 왼쪽은 해당 PID의 전체 원문, 오른쪽은 실제 OCR 입력/전사본/줄 단위 대조입니다. 다른 PID를 보려면 비교 창을 닫고 목록에서 선택합니다.

- AUTO_COPY_READ: 새 클립보드 값과 대상 출처를 확인한 자동 복사.
- OUTPUT_VISIBLE_EMPTY: 확인된 화면 본문에 보이는 내용 없음. 전체 버퍼는 미확인이고 저장 이미지로 판정을 확인할 수 있음. 복사 실패나 원문0자 수집 성공과 구분함.
- OUTPUT_READ: 모델이 전사 텍스트를 반환함. 정확도나 시뮬레이션 완료 인증이 아님.
- LOCATE_ONLY: Output 위치 확인 단계. 아직 OCR을 수행하지 않았음.
- SC_PENDING: Windows 응답 없음. 미수집이며 이전/다른 PID의 텍스트로 대체하지 않음.
- NOT_ATTEMPTED / TARGET_CANCELLED / TARGET_TIMEOUT: 미실행 / 취소 / 해당 PID 제한시간 초과.

원문 대조는 전체 텍스트 끝600줄에서 전사 행을 각 발생당 한 번 대응합니다. '원문 대응 없음0'은 이미지의 모든 줄을 읽었다는 뜻이 아닙니다. 실제 OCR 입력의 첫·마지막 줄과 숫자를 확인하세요. PowerSI가 버린 과거 로그는 복원하지 못합니다.

모델 변경은 비교 창만 닫고 LM Studio 설정에서 수행합니다. **같은 OCR 이미지 재판독**은 선택한 PID의 저장 PNG만 다시 읽으며 입력·복사·위치 탐색이 없습니다. 최근8개 실행을 PID별로 보관합니다. 새로운 전체 수집은 이전 배치를 대체하며, 수집 중 Stop은 완료한 PID 결과를 보존합니다.

## 설정·시간·로그

LM Studio에 이미지 지원 모델을 로드하고 서버를 켠 뒤 Slave의 **LM Studio 설정**에서 사용·자동 복사를 켜고 모델을 선택합니다. 포트 기본값1234, 요청 제한15~90초입니다. 모델별 thinking은 사용자가 OFF로 설정했으며 앱도 OFF를 요청합니다. 서버 적용은 확인하지 못하므로 로그의 effective=UNKNOWN은 유지합니다. 앱은 모델/GPU/시뮬레이션 설정을 바꾸지 않습니다.

창당 최대215초는 위치 요청·복사·OCR의 **상한**이며 기다리는 시험을 요구하는 시간이 아닙니다. 각 단계는 더 짧은 독립 제한이 있습니다. 첫 요청이 끝나면 다음 단계로 즉시 진행합니다. 8B의 이전 단일 OCR 시간은 위 표본의 값이지 복수 창 시험의 소요 시간 보장이 아닙니다.

OUTPUT_BATCH_BEGIN/COMPLETE, OUTPUT_TARGET_BEGIN/END는 대상 PID·시작 시각·결과·총 경과를 기록합니다. VISION_RUN에는 모델 ID/양자화, 전체·OCR 이미지 해시, 위치/OCR 시간과 형식 검사 메타데이터만 남습니다. LOCATE_ONLY는 위치 단계, 이어지는 LOCATE_OCR은 위치/OCR 합산 결과, OCR_ONLY는 사용자 재판독입니다. 원문·전사본·이미지는 로그나 기존 Master 통신에 넣지 않습니다. 원문 복사가 성공한 뒤 OCR만 실패해도 원문과 그 수집시각은 유지합니다.

진단 ZIP은 사용자가 저장 버튼을 누를 때만 생성합니다. 루트 manifest와 로그, targets/NN-pidPID/ 아래 각 PID의 manifest·전체 텍스트·실행별 이미지/전사본/대조 결과를 담습니다. **사내 원문과 화면을 Git·공개 저장소·외부 공유 채널에 올리지 않습니다.** 실행 중에도 로그 파일은 기록마다 닫힙니다.

## 기존 통신과 후속 단계

모바일 ↔ Master ↔ Slave의 정형 상태 왕복은 현장 검증됐습니다. 명령은 help, help pwrsi, help total status, total status, pwrsi이며 앞뒤 일반 공백/NBSP를 제거하고 새 동일 메시지를 새 요청으로 처리합니다. Master는 개별 자기 대화창만 사용합니다.

**Output 발췌문의 모바일 전달 및 여러 PID 결과의 통신 계약은 아직 미구현**입니다. 이번 시험은 로컬 수집만 검증합니다. 내부 pending 판별, Ansys HFSS/다른 프로그램 수집, 장기 대기/복구는 이후 과제입니다. 원격 실행·중단 기능은 이번 변경에 없습니다.

## 개발·배포

.NET Framework4.8, Windows 빌드입니다. 개발자는 scripts/build-package.ps1로 양쪽 Release 빌드·실제 EXE 자체 검사·패키지를 검증합니다. 사용자는 SELF-TEST.cmd나 PowerShell이 필요 없습니다.

CI workflow_dispatch의 새 release_tag로 GitHub Releases pre-release를 게시합니다. 현재 버전의 Slave-only ZIP은 Remote-Monitor-Slave-v0.1.57-win11-net48.zip이며 EXE/config/README/HANDOFF/SLAVE-TEST가 들어갑니다. 게시 상태·검증 근거·SHA256은 HANDOFF에서 확인합니다. 기존 태그나 자산은 덮어쓰지 않습니다. 이번에는 Slave만 교체하고 Master와 연결하지 않습니다.

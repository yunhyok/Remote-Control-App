# Remote Monitor v0.1.50 — 가림 없는 자동 복사와 클릭 후 확인

**다른 서비스에서 이어받기:** [HANDOFF.md](HANDOFF.md)에 목적·구조도·전체 진행 요약·확인된 결과·미완료 기능·다음 작업·빌드 방법을 정리했습니다. Claude 등의 시작 파일은 [CLAUDE.md](CLAUDE.md)입니다. 이전 단계 기록은 [PROJECT-REVIEW.md](PROJECT-REVIEW.md)이며 최신 상태와 구분해서 읽습니다.

휴대폰 KI-Messenger → Win7 Master → 사내망 Win11 Slave의 읽기 전용 상태 조회입니다. PowerSI와 LM Studio는 **같은 Slave 워크스테이션**에서 실행합니다.

## 이번 확인

현재 현장 시험은 **Slave만** 사용합니다. **두 방식 비교**를 한 번 실행하고, 수동 복사 안내가 나오면 Output 본문을 클릭한 뒤 Ctrl+A·Ctrl+C 합니다. 이 한 번의 수동 복사가 **자동 복사 위치 학습**입니다. 두 번째 **두 방식 비교**에서는 같은 PowerSI 인스턴스에 한해 앱이 **자기 창을 잠시 최소화하고** 그 위치를 클릭한 뒤 화면을 다시 확인해 Ctrl+A·Ctrl+C를 실행합니다. 모델을 바꿔 볼 때는 전체 비교를 반복하지 말고 **같은 화면 재판독**을 씁니다. 이어서 **원문 대조**와 **진단 묶음 저장**으로 전사본과 전체 텍스트의 차이를 확인합니다. [Slave 확인 방법](SLAVE-TEST.md).

**v0.1.49 현장 시험에서 위치 학습은 6번 모두 성공했지만 자동 복사는 5번 모두 중단됐습니다**(가림 4회, 본문 미확정 1회). 키는 한 번도 전송되지 않았습니다. **v0.1.50의 변경도 개발자 자체 검사만 통과했고 실제 PowerSI에서 검증되지 않았습니다.** 자동 복사가 실패하면 기존 30초 수동 복사 안내로 그대로 돌아갑니다. 진행률을 계산하지 않으며, 로그의 의미와 진행 상황은 사용자가 판단합니다.

Slave 시작/IP/연결파일, Master·메신저·모바일 시험은 필요 없습니다. Output 크기를 반복해서 바꾸거나 **PowerSI 확인**을 추가로 실행하지 않습니다. 모델 교체는 사용자가 LM Studio에서 하고 Slave의 **LM Studio 설정**에 현재 모델을 저장합니다. 두 모델 동시 로드, 다운로드, GPU 설정 변경은 요구하지 않습니다.

## v0.1.50에서 바꾼 것

**1. 자동 복사 동안 Slave 창을 스스로 최소화합니다.** v0.1.49 현장 실패 4건은 클릭 지점의 맨 앞 창이 PowerSI가 아니라는 `AUTO_COPY_OCCLUDED`였고, 로그만으로는 무엇이 가렸는지 알 수 없었습니다. 이제 UI가 메인 창과 열린 대화상자를 최소화한 뒤 worker를 시작하고(`OUTPUT_AUTO_COPY_BEGIN self_hidden=1`) 결과와 무관하게 원래 상태로 되돌립니다. 그래도 가려져 있으면 가린 창의 프로그램 이름을 `OCCLUDER|<이름>`으로, 우리 창이면 `OCCLUDER|SELF`로 남깁니다.

**2. 클릭한 다음에 화면을 확인합니다.** 순서가 "창 식별·client 크기·클릭 지점의 맨 앞 창 확인 → 클릭 1회 → 150ms → 새 캡처에서 본문 재확인 → 키 전송"으로 바뀌었습니다. 클릭이 직전 수동 Ctrl+A의 선택 강조를 지우므로 평평한 배경을 전제로 한 본문 검사가 반복 가능해집니다. 재확인한 본문은 클릭 지점을 포함해야 하고 학습 때 본문과 각 변8픽셀 이내여야 하며, 아니면 `AUTO_COPY_BODY_UNCONFIRMED`/`AUTO_COPY_BODY_MOVED`로 **키를 한 번도 보내지 않고** 중단합니다. 저장된 좌표를 그대로 믿고 누르는 것이 아니라, 살아 있는 창에서 확인한 지점을 한 번 누르고 그 결과 화면이 학습 때와 같을 때만 키를 보냅니다.

**3. 실패한 자동 복사의 화면을 남깁니다.** 캡처 이후에 중단된 경우 worker가 그 PNG를 UI로 돌려주고, UI는 마지막 1장을 메모리에 두었다가 진단 묶음에 `auto-copy-frame.png`로 넣습니다(manifest의 `auto_copy_last_failure`에 코드·detail). 파일로 자동 저장하지 않습니다.

**4. 본문 후보 규칙에 포함 조건을 더했습니다.** 후보는 제안 상자의 중심을 포함하거나, **후보 면적의 90% 이상이 제안 안에 들어 있으면** 통과합니다. 현장에서 31B Q4의 `320|385|1570|574`는 좌·상·높이가 맞고 폭만 과했는데 중심 규칙에만 걸려 탈락했습니다. 크기·채움·과대·겹침 규칙과 "채택 후보는 정확히 하나"는 그대로이며, 한 제안 안에 본문이 둘이면 여전히 확정하지 않습니다.

**5. 모델 사고 과정으로 답이 비는 경우를 구분합니다.** 두 요청에 `chat_template_kwargs.enable_thinking=false`를 넣고(모르는 서버는 무시합니다) OCR 요청의 최대 토큰을 4096으로 올렸습니다. 그래도 `finish_reason=length`이면서 `reasoning_content`만 있고 답이 비면 `INCOMPLETE_REASONING`으로 기록해 단순 길이 초과와 구분합니다. **사고 과정 텍스트는 어떤 경우에도 전사본으로 쓰지 않습니다.**

메인 창 아래 상태줄에 **최근 자동 복사 코드**가 함께 표시됩니다.

## v0.1.49에서 추가한 것 (그대로 유지)

**1. 학습한 위치 자동 복사.** 표준 객체 직독이 실패하고 **학습한 Output 위치로 자동 복사** 설정이 켜져 있으며 같은 PID·프로세스 시작시각·세션의 인스턴스가 그대로 실행 중일 때만 시도합니다. 별도 worker 프로세스(최대8초)가 창을 다시 찾아 client 크기·표시 상태·최소화 여부를 확인하고, 마우스 버튼·Ctrl·Shift·Alt·Win이 눌려 있지 않은지와 클릭 지점의 최상위 창이 대상인지 확인한 뒤 커서를 옮겨 **클릭 한 번**을 보냅니다. v0.1.50은 그 다음 새로 캡처한 화면에서 본문을 다시 확인하고, 확인된 뒤에만 **Ctrl+A 한 번 → Ctrl+C 한 번**을 보냅니다. 모든 키는 finally에서 해제하고 커서는 원래 자리로 되돌립니다. 클립보드는 복원하지 않습니다. 중단 코드는 `AUTO_COPY_WINDOW_CHANGED`, `AUTO_COPY_BODY_UNCONFIRMED`, `AUTO_COPY_BODY_MOVED`, `AUTO_COPY_INPUT_BUSY`, `AUTO_COPY_OCCLUDED`, `AUTO_COPY_CURSOR_NOT_SET`, `AUTO_COPY_CURSOR_MOVED`, `AUTO_COPY_FOREGROUND_FAILED`, `AUTO_COPY_FOREGROUND_LOST`, `AUTO_COPY_KEYS_FAILED`, `AUTO_COPY_NO_CLIPBOARD`, `AUTO_COPY_CLIPBOARD_FOREIGN`, `AUTO_COPY_TIMEOUT` 등이며, 실패하면 클립보드 기준값을 다시 읽고 수동 복사 안내로 돌아갑니다. 위치는 **메모리에만** 두고 파일로 저장하지 않으며 앱을 닫으면 사라집니다.

**2. 본문 탐색 진단 B2와 `OUTPUT_REGION_UNCONFIRMED`.** 본문 경계를 확정하지 못한 실행도 이제 `B2|화면폭|높이|후보수|채택수|크기탈락|채움탈락|과대탈락|중심·포함탈락|겹침탈락`를 남깁니다(v0.1.50에서 8번째 필드의 뜻만 넓어졌고 형식은 그대로입니다). 좌표·글자는 들어가지 않습니다. 경계 실패는 일반 판독 실패와 구분되는 `OUTPUT_REGION_UNCONFIRMED` 코드로 기록합니다.

**3. 원문 대조.** 비교 창의 전사본 아래에 전사본 각 줄을 전체 텍스트 끝부분(기본600줄)과 맞춰 본 결과를 표시합니다. 일치·정규화 일치(앞뒤/중간 공백만 다름)·근사(편집 거리 이내, 첫 차이 위치 표시)·누락·빈 줄과 줄 순서 유지 여부를 구분합니다. 로그에는 `T1|줄수|일치|정규화|근사|누락|빈줄|순서`만 남기고 본문은 화면과 진단 묶음에만 둡니다.

**4. 진단 묶음.** 비교 창의 **진단 묶음 저장…** 버튼으로만 만들어지는 ZIP입니다. 경고 확인 후 저장 위치를 직접 지정하며, 전체 텍스트·화면 이미지·전사본·대조 결과·실행 메타데이터·현재 진단 로그 사본이 들어갑니다. **사내 고유 정보가 그대로 들어 있으므로 Git이나 외부 공유 채널에 올리지 않습니다.** 로그에는 크기와 SHA256만 남기고 경로는 남기지 않습니다.

v0.1.47의 현장 로그에서는 E4B가 전사 텍스트를 반환했지만, 31B 두 양자화는 위치 찾기에 약44~50초를 사용한 뒤 OCR 중 전체100초 제한에 도달했습니다. v0.1.48은 이미 확보한 OCR 입력을 재사용해 위치 찾기 시간을 다시 쓰지 않고, OCR에 설정된 최대90초를 사용할 수 있게 합니다.

| v0.1.47 모델 | 위치 찾기 초 | OCR 초 | 전체 초 / 결과 |
|---|---:|---:|---|
| E4B Q6_K, 2회 | 7.051 / 5.128 | 4.288 / 4.050 | 11.755 / 9.609, 텍스트 반환 |
| 31B Q8_0 | 49.995 | 49.526 | 100.013, OCR 중 전체 제한 |
| 31B Q4_K_M | 43.735 | 55.662 | 100.013, OCR 중 전체 제한 |
| Qwen3.6-35B-A3B Q6_K_XL | 40.688 | 미실행 | 41.106, 위치 응답 미완료 |

Qwen 결과는 시간 초과가 아닌 `LOCATE_OUTPUT_INCOMPLETE_RESPONSE`이며, 기존 로그만으로 실제 토큰 한도 도달 여부는 알 수 없습니다. 별도 취소 실행에는 모델 기록이 없어 모델별 평가에 넣지 않습니다. 생성된 본문은 모두 `x=317, y=393, w=585, h=560`, OCR 입력은1170×512픽셀이었습니다. E4B와31B Q8은 전체/OCR 해시가 같았고, Qwen과31B Q4는 전체 해시만 같았습니다(Qwen은 OCR 입력 미생성). **로그에는 문자 정답이 없으므로 큰 모델과 작은 모델의 정확도 우열은 아직 판단할 수 없습니다.**

## 두 수집 방법과 선택 이유

| 방법 | 장점 | 현재 한계 |
|---|---|---|
| LLM 화면 판독 | 텍스트 객체가 없는 프로그램에도 적용 가능 | 보이는 범위뿐이며 숫자·문구 오류 가능. 최대12줄/2000자 |
| 표준 텍스트 객체 직접 읽기 | 화면 밖 줄/오른쪽에 잘린 문장도 버퍼에 있으면 정확히 읽음. 입력·클립보드·LLM 불필요 | 프로그램의 객체 노출/표준 컨트롤 지원 필요 |
| 선택·복사 | Ctrl+A/C를 지원하는 비표준 본문의 전체 텍스트 확보 가능 | 정확한 대상 선택과 클립보드 출처 확인 필요. 수동 복사 1회로 위치를 배운 뒤에만 자동 복사를 시도하며 현장 미검증 |

새 전체 텍스트 경로는 Output 이름을 native 컨테이너 또는 UIA의 non-root HWND에 연결하고, 그 안의 유일한 표준 multiline Edit/RichEdit를 `WM_GETTEXT`로 읽습니다. 자동 식별이 안 되면 먼저 학습된 위치로 자동 복사를 한 번 시도하고, 그 경로가 없거나 중단되면 같은 실행에서30초 동안 **Output 클릭 → Ctrl+A → Ctrl+C**로 새 수동 복사본을 받습니다. 두 경우 모두 작업 시작 이후 변경된 클립보드이면서 동일 PowerSI PID·시작시각·세션이 소유한 텍스트만 받습니다. 자동 복사도 Output 전체가 선택됐는지를 보증하지는 않으므로 원문 대조로 확인합니다.

전체 버퍼는 최대8Mi UTF-16문자이며 초과하면 잘라서 성공 처리하지 않습니다. RichEdit의64K 초과 직독 제한은 수동 복사 대안으로 구분합니다. [Microsoft WM_GETTEXT 문서](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-gettext). PowerSI가 이미 버린 과거 로그는 복원하지 못합니다. 직독 중 길이 변화는 거부하지만 같은 길이의 갱신까지 원자적 스냅샷을 보증하지는 않습니다.

본창은 끝부분4000자의 미리보기이며 **결과 비교 보기**의 왼쪽에는 전체 원문, 오른쪽에는 이미지와 LLM 전사본, 그 아래 **원문 대조**를 표시합니다. 기본 이미지는 **Output 전체 본문 — 제목줄 제외**입니다. 이미지 선택 상자에서 **문자 전사 입력 — 하단 확대**, LLM 제안 영역, PowerSI 전체 원본으로 전환할 수 있습니다. 전사본은 실제 **문자 전사 입력**의 숫자·단위·철자·줄 순서와 먼저 대조하고, 다음으로 왼쪽 원문의 해당 부분과 비교합니다. 원문 수집과 캡처는 시각이 다르지만 본문/확대 입력은 하나의 고정된 캡처에서 만듭니다. 전체 버퍼는 LLM에 보내지 않습니다.

**같은 화면 재판독**은 이전 결과의 실제 OCR PNG가 있으면 현재 Slave 설정 모델로 **문자 전사만** 실행합니다. 저장된 이미지 바이트를 그대로 사용하므로 `ocr_sample`도 유지됩니다. OCR 이미지가 아직 없으면 저장한 전체 화면으로 위치 찾기부터 실행합니다. 자동 재시도는 하지 않습니다. 비교 창 위쪽 실행 선택 상자에서 최근 최대8개 결과와 전체/OCR 입력 해시를 확인할 수 있습니다. 화면·원문·이력은 메모리에만 남으며, 새 **두 방식 비교**는 새 화면으로 시작합니다. 재판독 중 **Stop**은 이전 완료 이력을 유지하지만 대기 중 Stop은 이력을 비웁니다. 모델 교체 시에는 비교 창만 닫습니다.

LLM 위치 응답은 `OUTPUT_BOX left top right bottom`의 0~1000 정규화 좌표이며 프로그램이 원본 픽셀에 대응시킵니다. 범위 밖·뒤집힘·전체 이미지 지정 등은 거부합니다. 이어서 제안 영역의 중심 포함(또는 후보 면적 90% 이상이 제안 안)과 겹침, 원본 배경 경계가 맞는 본문 후보를 하나만 허용합니다. 경계를 확정하지 못하면 원래 제안 상자로 대신 전사하지 않습니다. 배경색 하나나 패널 위치를 고정하지 않지만, 평평한 중립색 배경을 전제로 한 임시 방법이므로 유효한 경계가 곧 Output 식별 성공을 뜻하지는 않습니다.

최초 본문 크롭은 원본 픽셀을 그대로 유지하며 제목줄을 제외합니다. 별도의 OCR 입력은 **본문 하단 최대256픽셀 행**입니다. 본문 폭이2048픽셀 이하면 최근접 방식으로 각 픽셀을2배 복제하고, 더 넓으면1배를 유지합니다. 이미지 생성이나 문자 보정은 하지 않습니다. 최초 위치 찾기와 OCR은 동일한 로드 모델에 이력 없는 별도 요청으로 보내며, 이후 OCR 입력 재사용은 현재 선택한 모델에 전사 요청만 보냅니다. 전사 프롬프트는 문자·문장부호·대소문자·숫자·단위·줄 순서 그대로 읽기, 요약·의역·오타 수정·가려진 문자 추측 금지를 명시합니다. 프롬프트만으로 준수를 보증하지 않습니다.

자동 복사는 **LLM이 제안한 좌표가 아니라 사용자가 실제로 클릭한 위치**를 현재 화면에서 다시 확인해 사용합니다. 저장된 이미지나 과거 좌표로는 절대 클릭하지 않습니다. 공식 로그 파일/내보내기가 확인되면 그 경로도 우선 검토합니다. 현재 이 버전의 Output과 일치하는 로그 파일 경로는 확인하지 못했으므로 임의 파일 탐색은 하지 않습니다.

## 최종 대상과 이번 시험의 구분

최종 목표는 **여러 PowerSI 인스턴스와 Ansys 등 여러 프로그램**의 실행/작업 정보 수집입니다. 현재 단일 PowerSI 창 조건은 수집 방식을 검증하기 위한 임시 제한입니다. 인스턴스 식별(PID·시작시각·세션), 수집, 표시/전송을 분리합니다. 다중 인스턴스 선택과 프로그램별 수집 정책은 추후 구체화하며 아직 범용 플러그인 틀이나 임의 프로그램 조작을 추가하지 않습니다.

## 데이터가 이동하는 범위

- Slave 앱은 PowerSI 창의 클라이언트 영역을 메모리 PNG로 캡처하고 본문 크롭·하단 확대 입력을 메모리에서 만듭니다. 데스크톱 전체나 다른 창을 대신 캡처하지 않습니다. 같은 화면 재판독은 이 저장된 PNG를 사용합니다.
- 이미지는 오직 `http://127.0.0.1:<설정 포트>`의 LM Studio로 보냅니다. 앱은 외부 URL·시스템 프록시·HTTP 리다이렉트·클라우드 대체 경로를 사용하지 않습니다.
- LM Studio는 **이 워크스테이션에 내려받아 로드한 로컬 모델**로 운용합니다. LM Link/원격 모델 중계는 사용하지 않습니다. 앱이 LM Studio 내부의 원격 실행 여부나 자체 로그 정책까지 통제하는 것은 아닙니다.
- 모델은 보이는 Output 로그를 옮겨 적습니다. 이 전사본은 정확도가 검증된 원본이 아니며, **현재는 Slave 화면에서만** 비교합니다. 거부된 응답도 최대40000자까지 Slave 메모리의 비교 화면에만 남기며 **UNVALIDATED**로 표시합니다.
- 기존 통신 프로토콜에는 프로세스 수치와 고정 결과 코드·캡처 시각만 넣습니다. 이미지, 전사본, 설계명, API 토큰은 넣지 않습니다. **로그 발췌문을 메신저로 전달하는 연결은 판독 확인 이후 단계이며, 이번 버전에서 구현·시험하지 않습니다.**
- LLM 결과를 실행 명령으로 사용하지 않습니다. 화면 속 지시문도 명령으로 취급하지 않습니다. 프로그램 실행/종료·시뮬레이션 조작 기능은 이번 범위에 추가하지 않았습니다.
- 전체 버퍼/복사본은 Slave 메모리에서만 표시하고 LM Studio·기존 상태 프로토콜·메신저로 보내지 않습니다.
- **v0.1.49부터 앱도 입력을 만듭니다.** 자동 복사 경로에서만 클릭 한 번과 Ctrl+A·Ctrl+C 한 번을 보내며, 이때 커서가 잠시 이동했다가 원래 위치로 돌아오고 **Windows 클립보드 내용이 바뀝니다**(복원하지 않습니다). v0.1.50부터는 그동안 **Slave 창과 열린 대화상자가 스스로 최소화됐다가 원래 상태로 돌아옵니다.** 다른 프로그램의 창은 건드리지 않습니다. 그 밖의 캡처·판독·수동 복사 대기 경로는 이전과 같이 입력을 만들지 않습니다. 학습한 위치는 메모리에만 있고 앱을 닫으면 사라지며, 설정에서 자동 복사를 끌 수 있습니다.
- **진단 묶음 ZIP은 사용자가 버튼으로 요청할 때만** 만들어지는 로컬 파일입니다. 화면 이미지와 Output 전체 텍스트, v0.1.50부터는 자동 복사가 실패했을 때의 화면 1장이 그대로 들어가므로 Git·외부 공유 대상이 아니며, 저장 위치는 사용자가 지정하고 로그에는 크기와 SHA256만 남습니다.

## 모델과 LM Studio

LM Studio **0.4.0 이상**의 `/api/v1/models`에서 현재 로드된 모델 인스턴스와 이미지 지원 정보를 확인합니다. 모델명이나 Gemma 버전을 코드에 고정하지 않습니다. 모델 ID를 비워 두면 로드된 이미지 모델이 정확히 하나일 때만 자동 선택합니다. 모델이 교체·해제되거나 여러 개면 선택/확인을 요구하며, 앱이 다운로드·로드·언로드하지 않습니다.

설정은 Slave의 **LM Studio 설정**에서 바꿉니다. 같은 창에 **학습한 Output 위치로 자동 복사 (클릭·Ctrl+A/C 한 번)** 체크가 있으며 기본값은 켜짐입니다. 이 설정만 끄면 앱은 이전처럼 입력을 전혀 만들지 않고 수동 복사 안내만 사용합니다. 포트 기본값 1234, 각 모델 호출 제한 기본값60초(15~90초), LLM 전체 제한100초는 유지합니다. 이번 **31B Q4 재판독은 호출 제한을90초로 저장**합니다. OCR 입력을 재사용하면 앞선 위치 찾기 없이 OCR 한 번에 이 제한을 적용합니다. 인증 토큰은 LM Studio에 설정했을 때만 입력하고, 저장 시 Windows 현재 사용자 DPAPI로 암호화합니다. 설정은 Slave 수신과 판독이 진행 중이지 않을 때 바꿀 수 있으며, 비교 창만 닫고 설정으로 이동합니다. 기존 [LM Studio Chat Completions](https://lmstudio.ai/docs/developer/openai-compat/chat-completions) 요청 경로를 재사용합니다.

같은 워크스테이션에서 시뮬레이션과 모델이 자원을 공유하므로, 앱이 모델 메모리/GPU 설정이나 PowerSI 설정을 자동 변경하지 않습니다.

## 명령

| 입력 | 답장 |
|---|---|
| `help` | 사용 가능한 명령 목록 |
| `help help`, `help total status`, `help pwrsi` | 해당 명령 설명 |
| `total status` | Slave 시각·가동 시간·RAM·프로그램 목록/PID/CPU/메모리 |
| `pwrsi` | powersi/pwrsi 프로세스 정보 + 고정 판독 결과 코드·캡처 시각 (발췌문은 현재 Slave에서만 표시) |

소문자로 입력합니다. `pwrsi`에는 공백이 필요 없고, `total status`는 단어 사이 한 칸입니다. 앞뒤 일반 공백(U+0020)·NBSP(U+00A0)는 제거합니다. 같은 문구도 새 메시지면 새 요청이며 과거 메시지를 실행하지 않습니다.

답장은 영문 대문자로 표시하여 자기 응답이 명령으로 되돌아오는 것을 막습니다. D 뒤 숫자는 답장 식별값이며 입력할 코드가 아닙니다. 평문 모드에는 M/NEXT 코드가 없습니다.

## 결과 읽기

- `VISION MODEL_READ`: 모델의 화면 판독 결과입니다. PowerSI API에서 검증된 내부 상태라는 뜻이 아닙니다.
- `CAPTURE UTC`: 화면을 캡처한 시각입니다. 모델이 답변을 완료한 시각과 구분합니다. 일반 프로세스 수치는 조회 시작 무렵 약0.5초 표본입니다.
- `OUTPUT_READ`: 모델이 텍스트를 반환했다는 뜻입니다. 정확한 OCR이나 시뮬레이션 완료를 보증하지 않습니다. 주파수·경고·진행률을 따로 해석하지 않습니다.
- `OUTPUT_UNAVAILABLE`: 모델이 Output을 읽을 수 없다고 응답했습니다. 시뮬레이션 실패라는 뜻은 아닙니다.
- 본창에는 최근 로그 전사본과 캡처 시각을 먼저 보여줍니다. 최대12줄·2000자이며, 제한을 넘으면 앞부분 생략을 표시합니다. 명시적인 완료 문구가 발췌 범위에 있으면 문구 그대로 확인합니다.
- Slave의 **캡처 / 판독 원문 보기**로 모델에 보낸 이미지와 모델이 옮긴 텍스트를 같은 결과에서 비교할 수 있습니다. 형식 검사 실패 시에는 고정 실패 코드와 거부된 응답을 표시합니다. 제어/방향 지정 문자는 미리보기에서 대체하며 40000자 이후는 생략합니다. 앱은 이미지/원문을 파일이나 로그에 저장하지 않습니다.

기존 LLM 경로는 PowerSI API나 Output 객체 이름에 의존하지 않습니다. 창 크기/패널 위치는 고정하지 않지만 Output은 읽을 수 있는 크기로 보여야 합니다. 화면에 없거나 잘린 문장은 복원하지 않도록 요청합니다. 최소화·잠금·세션 연결 해제·복수 PowerSI 창은 현재 시험에서 확인 불가입니다. 창 캡처 성공만으로 모든 패널의 정상 렌더링이나 모델의 지시 준수를 보증하지 않습니다.

## 시간·취소·로그

비교 실행은 LLM 판독과 전체 텍스트 읽기를 병행합니다. 직독 worker 최대10초, 수동 복사 대기30초, 복사 데이터 읽기 worker 최대3초, 전체 비교105초 제한입니다. 내부100초 제한의 크롭/오류 결과를 반환할 여유를 포함합니다. 클립보드 지연 렌더링도 별도 worker에서 처리하여 Stop이 멈추지 않도록 했습니다. `OUTPUT_BUFFER` 로그에는 고정 결과/방법, 글자·줄 수와 `B1|native객체수|Output범위수|표준본문후보수|UIA방문수`만 남깁니다. 자동 복사 성공은 `result=AUTO_COPY_READ method=AUTO_CLIPBOARD`와 `detail=A2|학습x|학습y|본문x|y|w|h|클릭화면x|클릭화면y|B2|…`입니다. `OUTPUT_VISION_CAPTURE/LOCATE_OUTPUT/CROP_OUTPUT/READ_CROP`는 실행 단계입니다. 텍스트 본문은 기록하지 않습니다.

v0.1.49가 추가하고 v0.1.50이 이어 쓰는 줄은 `OUTPUT_AUTO_COPY_BEGIN self_hidden=1`, `OUTPUT_AUTO_COPY_FAILED code=… detail=…`(detail은 `B2|…` 또는 `OCCLUDER|…`), `OUTPUT_ANCHOR_LEARNED anchor=A2|…|본문x|y|w|h body=x|y|w|h diag=B2|…`, `OUTPUT_ANCHOR_UNCONFIRMED reason=FRAME_MISSING|SIZE_MISMATCH|BODY diag=…`, `TRANSCRIPT_COMPARE summary=T1|…`, `DIAG_BUNDLE_SAVED bytes=… sha256=…`, `DIAG_BUNDLE_FAILED code=…`입니다. 모두 고정 코드·정수·해시뿐이며 경로·본문·전사본은 들어가지 않습니다.

캡처는 별도 단발 작업으로 최대 약4초입니다. 모델 판독은 설정 제한, 전체 Slave 판독은 최대100초입니다. 일반 상태/인증 제한은 기존8초이고, 인증된 PWRSI 요청만 서버105초·Master115초까지 허용합니다. 향후 연결 운용을 재개할 때는 버전 검사가 있으므로 양쪽을 같은 버전으로 맞춥니다. **이번에는 Slave만 교체하고 기존 Master와 연결하지 않습니다.**

Slave에는 판독 중 경과 시간과 완료 상태가 표시됩니다. **Slave Stop**은 로컬 캡처/HTTP 대기를 취소합니다. **Master Stop**은 메신저/응답 대기를 중단하며 Slave의 진행 중 판독이 즉시 취소되는 것은 아닙니다. 그 작업도 자체 제한 안에서 끝납니다. HTTP 취소가 LM Studio 내부 계산의 즉시 중단까지 보장하지는 않습니다. 불확실한 전송은 자동 재시도하지 않습니다.

로그는 앱이 살아 있어도 각 기록 후 파일을 닫습니다. 버전·고정 결과/오류 코드·캡처 시각 외에 `VISION_RUN`은 `model_id`, `model_name`, `model_key`, `quantization`, 전체 PNG의 SHA256 `sample`, OCR 입력 PNG의 SHA256 `ocr_sample`, `total_ms`/`locate_ms`/`read_ms`를 기록합니다. **`mode=OCR_ONLY crop_reused=1`은 기존 OCR 입력 재사용**, `mode=LOCATE_OCR crop_reused=0`은 위치 찾기부터 실행한 결과입니다. `geometry=P2|제안x|y|w|h|본문x|y|w|h|OCR폭|높이`로 원본 픽셀 좌표와 실제 OCR 크기를 구분하고, v0.1.49부터 `frame=폭x높이`와 `body=B2|…` 본문 탐색 수치를 함께 남깁니다. OCR 재사용의 제안/본문 좌표는 이전 입력을 만든 실행의 값이며 현재 모델이 다시 찾은 좌표가 아닙니다. 실패 시 확인된 부분만 남을 수 있고, 없는 모델·표본·좌표 정보는 `UNKNOWN`입니다.

위치 찾기를 다시 하면 같은 `sample`에서도 OCR 입력이 달라질 수 있지만, **OCR 입력 재사용은 `ocr_sample`이 같은 상태에서 숫자 판독 품질을 비교**합니다. 원문과의 실제 대조 없이 시간 초과·응답 반환만으로 정확도를 판단하지 않습니다. 31B에서도 틀렸다는 결과만으로 프롬프트 문제라고 단정하지 않습니다. Google은 Gemma 4의 시각 토큰 예산에 따라 보존되는 이미지 세부 정보가 달라지며 OCR·작은 글자에는 더 높은 예산을 권장한다고 설명합니다. [Gemma 4 이미지 해상도 문서](https://ai.google.dev/gemma/docs/core/model_card_4#5-variable-image-resolution). 이번 실행의 모델·이미지 처리 조건을 함께 확인하되 설정을 자동 변경하지 않습니다.

최초 `total_ms`에는 캡처가 포함되고 재판독에는 포함되지 않습니다. OCR 입력 재사용은 `locate_ms=0`이며, 문자 전사 소요 시간은 `read_ms`로 비교합니다. 이 값도 모델 목록 조회·HTTP 대기를 포함하며 순수 GPU 생성 속도는 아닙니다. `request_timeout_s`에는 해당 실행에 적용한 호출 제한을 기록합니다. v0.1.48부터 `INCOMPLETE_LENGTH`는 응답이 명시적으로 길이 제한 종료를 알린 경우를 구분하며, 과거 Qwen의 일반 미완료 코드에 이 원인을 소급하지 않습니다. v0.1.50은 그중에서도 **사고 과정만 토큰을 쓰고 답이 빈 경우**를 `INCOMPLETE_REASONING`으로 따로 남깁니다.

`PWRSI_LOCAL_FAILURE`는 모델 목록, HTTP 형식, 바깥 응답 구조, 본문 종류·길이·제어문자 실패를 구분합니다. HTTP의 바깥 JSON·완료 표시·도구 호출 거부 검사는 유지합니다. 전체 원문·전사본·거부된 응답·이미지·프롬프트·토큰은 로그에 기록하지 않습니다. 설정 파일/연결 파일도 진단 로그에 첨부하지 않습니다.

## 기존 운용과 개발 검증

Master는 별도 **개별 자기 대화창**을 인식하며, 검증된 입력·커서 이동·클릭 전송을 요청당 한 번만 수행합니다. Send 위에 미리 마우스를 놓을 필요는 없습니다. Master 창/전경 변경이나 입력 간섭은 중단 사유입니다. Slave 캡처는 창 활성화·마우스/키보드 입력을 하지 않습니다.

`Remote-Monitor-Slave-v0.1.50-win11-net48.zip`은 Slave .NET Framework 4.8 EXE/config와 README/SLAVE-TEST를 포함하며, GitHub 인수인계 이후 빌드는 HANDOFF도 포함합니다. 전체 `Remote-Monitor-v0.1.50-win7-win11-net48.zip`에는 Master EXE/config와 보관용 WIN7-TEST가 추가됩니다. 현재 시험에서는 Slave만 실행합니다. 사용자에게 SELF-TEST.cmd 실행을 요구하지 않습니다. 내부 검사는 본문 경계 후보·포함 규칙·B2 진단 수치·앵커 직렬화/식별(A1·A2)·가린 창 이름 접기·worker 화면의 OB1 왕복·입력 패킷 구성과 소유한 시험 창에서의 클릭·Ctrl+A/C, 원문 대조 상태 분류, 진단 묶음 항목/해시, 픽셀 복제·하단 보존·요청 이미지 구분·실행/이미지 선택·같은 OCR PNG 재사용·현재 모델 선택·취소·로그 제외, 기존 전체 버퍼/LLM/통신 검사를 포함합니다. **실제 PowerSI에서의 자동 복사·원문 대조·진단 묶음과 숫자 전사 정확도는 아직 현장 확인 대상입니다.** 장시간 대기는 후순위입니다.
